# bigbear-device-record 操作手册

> 路径：`apps/bigbear-device-record/`
> 形态：Python CLI（FastAPI + Playwright + `npx` 调用 `@midscene/<platform>@1`）
> 作用：Android / iOS / HarmonyOS / PC 多平台设备画面采集，输出与 `bigbear-web-record` 兼容的 JSON，下游 case-generator 可直接消费

---

## 1. 它是什么 / 不是什么

| ✅ 是 | ❌ 不是 |
|---|---|
| 设备画面录制器（截图 + UI dump + 可选 vision 分析） | 自动化执行器（不能 click / type / assert） |
| 一个起本地 HTTP 服务 + 打开浏览器的 GUI 工具 | 后台守护进程（关闭浏览器就退出） |
| 一次 CLI 运行 = 一次批次（同一批次号目录） | 持久服务（重新启动会换批次号） |

CLI 主入口 `bigbear_device_record.cli:main` → 当前只暴露 1 个子命令：`record`。

## 2. 安装

### 2.1 PyPI 安装（推荐给最终用户）

```bash
pip install bigbear-device-record
```

### 2.2 源码安装（开发场景）

```bash
cd apps/bigbear-device-record
pip install -e ".[dev]"     # 基础依赖 + pytest/httpx
pip install -e ".[vision]"  # 叠加 openai SDK（启用 --enable-vision 才需要）
```

> 主依赖：fastapi / uvicorn / pydantic / pillow / pyyaml / **playwright==1.57.0** / python-dotenv
> Vision 依赖：`openai>=1.0.0`（通过 `openai` 兼容协议调用多模态模型）

### 2.3 浏览器二进制（首次必须）

```bash
playwright install chromium
```

工具用 Playwright 打开 `http://127.0.0.1:8765` 渲染录制页面，缺 Chromium 直接报错。

## 3. 命令全集

```bash
bigbear-device-record record \
  --platform {android|ios|harmony|pc}     # 必填
  [--device-id <serial>]                  # 不填取第一台设备
  [--output, -o  <dir>]                   # 默认 ./AI-信息采集
  [--host <ip>]                           # 默认 127.0.0.1
  [--port <int>]                          # 默认 8765
  [--fps <1-60>]                          # 默认 2（实时投屏帧率）
  [--enable-vision]                       # 默认 false
  [--no-browser]                          # 不自动打开浏览器
  [--debug]                               # 步骤级调试日志
  [--verbose, -v]                         # DEBUG 级 logging
```

> ⚠️ CLI 参数层面 `--enable-vision` 默认 **关闭**；但本工作区的 `bigbear-android-record` skill 在调用时默认是开启的（业务约定不同）。

## 4. 平台支持矩阵（源码实际可跑情况）

| 平台 | list 设备 | 截屏 | UI 层次 | 底层 |
|---|---|---|---|---|
| **pc** | ✅ | ✅ | `""` 占位 | `@midscene/computer@1` |
| **android** | ✅ `adb devices -l` | ✅ | ✅ 走 uiautomator dump | `@midscene/android@1` |
| **ios** | ✅ 仅 macOS 走 `xcrun simctl list devices --json` | ✅ | ✅ | `@midscene/ios@1` |
| **harmony** | ✅ `hdc list targets` | ✅ | ✅ | `@midscene/harmony@1` |

> iOS 仅在 macOS 上能列出设备；其他平台在 Windows 上跑会拿到 `[]`。

## 5. 安卓端典型操作流程

### 5.1 前置环境

| 项目 | 来源 | 校验命令 |
|---|---|---|
| adb | Android Platform Tools | `adb devices -l` 至少一台 `device` |
| Node.js ≥ 18 | 官网安装 | `node -v` & `npx --version` |
| Chromium | Playwright | `playwright install chromium` |

设备调试授权：手机 `设置 → 开发者选项 → USB 调试 = 开`，首次连接弹窗勾选"始终允许"。

### 5.2 启动录制

```bash
cd <你的项目根>    # 比如 Android测试/
bigbear-device-record record --platform android --enable-vision
```

效果：

1. 调 `adb devices -l` 解析设备列表，取第一台
2. 调 `npx -y @midscene/android@1 connect --deviceId <serial>` 建立 midscene 连接
3. 起 `uvicorn` HTTP 服务在 `127.0.0.1:8765`
4. 自动用 Playwright 打开浏览器到 `/`
5. 后台按 2fps 拉设备截图 → WebSocket 推帧 → 左侧实时显示

### 5.3 多台设备时指定

```bash
bigbear-device-record record --platform android \
  --device-id RFCN1234ABCD --enable-vision
```

serial 取自 `adb devices -l` 第一列。

### 5.4 录制 UI 操作

- 左侧：实时设备画面（live 模式）
- 右上：填 **Module**（必填，如 `电商-购物车`）、**Func**（可选）、**Desc**（可选）
- 点 **📸 SNAP**：触发一次 `take_screenshot` + `uiautomator dump`，落到批次目录
- 可多次 SNAP，每次生成 `screenshot_NNN.png` + `android_NNN.json`
- 关闭浏览器 = 退出本次会话（`server.should_exit = True`）

### 5.5 关闭浏览器即结束

源码 `_run_record_async` 中监听 `page.on("close")` 与 `context.on("close")`：任一事件触发 → `browser_closed_event.set()` → `await server_task` → `disconnect()`。

> `mode="live"` 连续 3 次截图失败后，会自动切到 `mode="snapshot"`（按需截）并推送一条错误消息。

## 6. 输出目录布局

按 `Storage._get_batch_dir()`：批次号 = `datetime.now().strftime("%Y%m%d-%H%M%S")`，**整次 recorder 运行复用同一个批次号**。

```
<output>/                                ← --output，默认 AI-信息采集
└── <batch_id>/                          ← 例如 20260805-220000
    └── <module>/                        ← module 用 "-" 或 "/" 拆多级，自动过滤 . / ..
        ├── img/
        │   └── screenshot_001.png
        └── json/
            ├── android_001.json
            ├── android_002.json
            └── android_003.json
```

模块名拆分规则（`storage._module_parts`）：

- `"人事管理-企业员工"` → `["人事管理", "企业员工"]`
- `"电商/购物车"` → `["电商", "购物车"]`
- 空段、`.`、`..` 全部过滤（防止路径穿越）

JSON 自增序号规则：在 `<module>/json/` 下扫 `android_*.json`，取最大编号 +1；同 module 多录不会覆盖。

## 7. JSON Schema（与 bigbear-web-record dom_NN.json 完全对齐）

```json
{
  "content": "<uiautomator dump XML 字符串>",
  "img": "img/screenshot_001.png",
  "module": "电商-购物车",
  "func": "结算",
  "desc": "",
  "interface_desc": "AI 视觉分析-界面整体描述",
  "layout_desc": "AI 视觉分析-布局描述",
  "elements_desc": "AI 视觉分析-元素描述列表"
}
```

> - `content` 在 PC 端是空串（PC connector 没实现 UI dump）
> - `interface_desc / layout_desc / elements_desc` 仅在 `--enable-vision` 启用且调用成功时存在
> - 写入走原子写（`tmp → os.replace`），中途崩溃不会破坏已有文件

## 8. Vision AI 配置

### 8.1 环境变量

CLI 在 `cli._make_vision_config` 中读取：

| 变量 | 必填 | 默认 |
|---|---|---|
| `DEVICE_VISION_API_KEY` | 是 | — |
| `DEVICE_VISION_BASE_URL` | 是 | — |
| `DEVICE_VISION_MODEL` | 否 | `qwen3.6-flash-2026-04-16` |

**读取规则（`cli._load_cwd_env`）**：只读**执行命令时当前工作目录**下的 `.env`，**不**查用户目录、安装目录、父目录；系统环境变量优先于 `.env` 同名变量。

### 8.2 模板

```bash
# .env（放在执行 bigbear-device-record 时所在的目录）
DEVICE_VISION_API_KEY=sk-xxxxxx
DEVICE_VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DEVICE_VISION_MODEL=qwen3.6-flash-2026-04-16
```

### 8.3 缺失保护

启动时若 `--enable-vision` 但 KEY 没配：

```text
[--enable-vision 但 DEVICE_VISION_API_KEY 或 DEVICE_VISION_BASE_URL 未配置，vision 关闭]
```

不会中断运行，只是不调用 vision。

### 8.4 Prompt 与容错

vision 调用走 OpenAI 兼容 `chat.completions`，prompt 强制要求返回纯 JSON `{interface_desc, layout_desc, elements_desc}`。

解析失败有 3 道兜底：标准 `json.loads` → 提取 ```json 块 → 提取首尾 `{...}`；再失败则记错误并跳过本次 vision 结果（**不会破坏已存的截图/JSON**）。

## 9. HTTP 服务接口（默认端口 8765）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 录制页面（`static/index.html`） |
| GET | `/api/devices?platform=pc\|android\|ios\|harmony` | 列设备 |
| POST | `/api/snapshot` | 触发一次截图（body: `module, func, desc, enable_vision`） |
| GET | `/api/output/tree` | 浏览已采集批次树 |
| WS | `/ws/...` | 实时投屏帧推送（详见 `server/ws.py`） |

> `/api/snapshot` 主要给前端或外部脚本做降级触发，正常流程走 UI 上的 📸 SNAP。

## 10. 进程与日志

- 启动后 `asyncio` 跑两个 task：`uvicorn.serve()` + 浏览器拉起/等待关闭
- 浏览器关闭 → 设 `server.should_exit = True` → `await server_task` → `manager.disconnect()`
- 日志级别：
  - 默认 `INFO`：`%(asctime)s [%(levelname)s] %(name)s: %(message)s`
  - `--verbose` 切到 `DEBUG`
  - `--debug` 走自定义 `set_debug()`，打开 `debug()` / `step()` 助手（步骤级打点）

## 11. 常见问题与排查

| 现象 | 排查 |
|---|---|
| `Node.js/npx not found on PATH` | 装 Node.js ≥ 18，重启终端 |
| `adb: command not found` | 装 Android Platform Tools 并加入 PATH |
| 设备列表为空 | `adb devices -l` 看 `state`，`unauthorized` 时手机点"允许 USB 调试"，`offline` 时 `adb kill-server && adb start-server` 重连 |
| `midscene take_screenshot timed out` | 设备可能锁屏/灭屏，先 `adb shell input keyevent KEYCODE_WAKEUP` 再试 |
| `Screenshot saved:` 解析不到 | midscene 版本不一致，重装 `@midscene/android@1` |
| 浏览器没自动弹出 | 用 `--no-browser=false`；或者用 `--no-browser` 后自己访问 `http://127.0.0.1:8765/` |
| vision 没结果 | 看 `.env` 是否在 cwd、KEY 是否配；启动日志里有 `DEVICE_VISION_API_KEY=已设置/未设置` 打点 |
| 端口被占 | `--port 8766` 换一个 |
| vision 调用慢 | 截图分辨率大；可关掉 vision 或调小 fps |
| 同一次运行产物落在不同目录？ | 不会——批次号一次运行内复用，重启才会换 |

## 14. 给当前项目（bigbear-case-project）的具体落地建议

1. **统一跑在哪？**
   安卓测试场景下，把命令行放在 **Android 测试项目根目录** 下执行；`AI-信息采集/` 自然落在项目根，与 `AI-测试点分析/`、`AI-自动化测试用例/` 形成华测标准三件套并列。

2. **Vision KEY 怎么配？**
   当前 `.env` 里只有 `AI_*` / `AGENT_AI_*` / `WEB_AUTOMATION_AI_*`，**没有 `DEVICE_VISION_*`**。需要新建或追加：

   ```bash
   DEVICE_VISION_API_KEY=<key>
   DEVICE_VISION_BASE_URL=<url>
   DEVICE_VISION_MODEL=qwen3.6-flash-2026-04-16   # 或你们用的多模态模型
   ```

   这套 KEY 与 `AI_*` 互不影响，**单独配**即可。

3. **与下游的衔接**
   录制的 JSON schema 与 `bigbear-web-record dom_NN.json` 一致，下游 `bigbear-device-case-generator` / `bigbear-web-case-generator` 不需要任何特判就能消费。

4. **批次目录管理**
   一次 CLI 运行 = 一个批次号；多次 SNAP 落在同一目录；不同模块通过 module 拆子目录。需要"合并多次跑的数据"时，自己按 batch_id 聚合即可。

5. **遇到 adb 设备问题时**
   按本文 §11 顺序排查：先 `adb devices -l` 看 state、再 `adb kill-server && adb start-server`、最后看手机 USB 调试授权弹窗。
