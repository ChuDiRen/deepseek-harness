# API 接口文档 Markdown 模板

本文档只定义 `bigbear-api-doc-generator` 最终输出的单接口 Markdown 文件结构。生成策略、事实性约束、二次运行行为见 `apidoc-spec.md`。

## 文件命名

`{seq:03d}_{METHOD}_{path_safe}.md`（下划线连接）

示例：
- `001_POST_user_login.md`
- `002_GET_user_userIndex.md`
- `003_GET_api_index_get_department_select.md`

字段说明：
- `seq` —— dedupe 后的次序，3 位补零；保证唯一、稳定
- `METHOD` —— HTTP 方法，大写
- `path_safe` —— path 去掉首尾斜杠，斜杠替换为 `_`，再清洗非法字符

> **冲突降级**：理论上 dedupe 后不可能冲突；万一出现 → `{base}__2.md` → `{base}__3.md`。
>
> **非法字符**：`< > : " / \ | ? *` 自动替换为 `_`。
>
> **二次运行**：对同一个 `raw.json` 重新执行时**直接覆盖**同名 MD 文件，**不备份**。要保留历史版本请提前 `cp` 一份，或用 `--output-dir` 输出到不同目录（与 `apidoc-spec.md` 一致）。

## 填写规则

- 模板中的 `{...}` 必须替换为真实内容或统一占位文本，不保留花括号占位。
- raw 中缺失的信息统一写 `待补充`，代码块内写 `// 待补充：请提供真实数据`。
- 不删除章节；没有数据也保留章节并明确标注未捕获。
- 每个接口独立一个 Markdown 文件。
- 用户可在生成后**自由重命名**文件、修改标题、补充业务描述——脚本不会再覆盖这些手工内容。但**重新跑同批次**会**直接覆盖**输出目录下的同名 MD 文件，**不备份**；要保留手工修改请先 `cp` 一份。
