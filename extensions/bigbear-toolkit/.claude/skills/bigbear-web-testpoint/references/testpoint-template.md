# AI-WEB 测试点分析 Markdown 模板

本文档只定义 `bigbear-web-testpoint` 的最终输出结构。分析原则、批次规则、公共模块策略和自检规则见 `testpoint-spec.md`。

## 页面测试点文件命名

`<功能名>.md`

示例：`登录.md`

## 页面测试点文档模板

```markdown
---
convert: mindmap
---

# 【<功能名>】测试点分析

## 基础信息

- 批次号：<batch>
- 功能名称：<功能名>
- 前置条件：<未登录/已登录/具备权限/无特殊前置条件>

## 页面来源

- 页面 URL：<页面 URL，未知则写“未提供”>
- 页面标题：<页面标题，未知则写“未提供”>
- DOM 文件：<dom_X.json相对路径地址>
- 截图文件：<screenshot_X.png相对路径地址>
- 页面截图：<从本文档到截图的相对路径>

## 全局公共模块

- 引用：<到 AI-测试点分析/全局通用功能/00_全局通用模块.md 的相对路径>
- 处理规则：本文档只分析当前功能专属区域
- 公共区域：<页头导航/页脚链接/全局搜索/无>

## 页面元素说明

### <元素名称>

- 类型：自然语言描述加dom元素标签。例如：按钮(button)、容器(div) 
- 示例：<DOM 中的文案或 placeholder>
- 可操作：是/否
- 作用：<业务含义>

## 功能测试点

### <功能分组>

#### <测试点名称>

- 操作：<用户操作>
- 数据：<测试数据，没有则写“无特殊数据”>
- 预期：<界面变化、提示、跳转目标或数据变化>
- 覆盖元素：<相关页面元素>

## 状态测试点

### 初始状态

- 触发：首次进入页面
- 预期：页面核心元素完整显示

### 交互状态

- 触发：点击、输入、勾选、悬停等交互
- 预期：控件状态、样式或提示正确变化

## 边界条件

### 空值校验

- 数据：必填项为空
- 操作：提交表单
- 预期：显示明确校验提示，阻止提交

## 业务跳转

### <跳转入口>

- 操作：点击 <入口名称>
- 预期：跳转到 <目标页面名称>
- 说明：不臆造具体路由，仅记录可见跳转目标
```
