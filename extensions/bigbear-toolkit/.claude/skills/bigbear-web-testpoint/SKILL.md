# BigBear Web TestPoint（单批次版）

## 核心能力

基于 `AI-信息采集/{批次号}/{模块路径}/` 下的 DOM JSON、页面截图和页面上下文，生成可导入思维导图工具的 Markdown 测试点分析文档。

适配工具包括 XMind、幕布、Markmap、ProcessOn、GitMind 等按 Markdown 标题和列表生成节点的工具。

**本技能每次处理一个明确的批次**——不主动扫描整个工作空间找批次。

## 产物模板与规范

本技能有明确输出物：页面测试点分析 Markdown 与全局公共模块 Markdown。执行前必须按需读取：

- `references/testpoint-template.md`：页面测试点与全局公共模块的最终 Markdown 模板
- `references/testpoint-spec.md`：批次读取、分析边界、输出规则、公共模块策略和自检规范

硬性要求：最终产物结构以 template 为准，生成行为和质量要求以 spec 为准。

## 工作目录约定

```
{工作空间}/                          ← 项目根目录
├── AI-信息采集/{批次号}/{模块路径}/      ← 输入
│   ├── json/dom_001.json
│   └── img/screenshot_001.png
├── AI-测试点分析/{模块路径}/            ← 输出
│   └── <功能名>.md
├── AI-测试点分析/全局通用功能/
│   └── 00_全局通用模块.md
└── AI-测试用例/
    └── {模块路径}/<功能名>_测试用例.md
```

## 触发条件

满足其一：
- 用户说"分析测试点" / "生成测试点" / "测试点分析" / "根据指定批次生成WEB测试点文档" + **明确提供批次号**
- 用户提供具体 JSON 文件路径

## 执行流程

### 第一步：判断用户是否指定了具体批次

检查用户输入是否包含：
- 批次号（如 `20260609-223046`）
- 批次目录路径
- 具体 JSON 文件路径

如果**指定了** → 直接进入第三步。
如果**未指定** → 询问用户批次号，或让其说"扫一下批次"。

### 第二步：（可选）扫批次

**仅当用户明确要求**才跑：

```bash
python .claude/skills/bigbear-web-testpoint/scripts/scanner.py --list-batches
```

> **默认不跑**。

### 第三步：scanner.py 解析指定批次

```bash
python .claude/skills/bigbear-web-testpoint/scripts/scanner.py --batch "<批次号>" --json
```

scanner 输出每个 feature（页面）的 JSON 列表、截图数量、输出目录。

### 第四步：main flow 直接处理每个 func

Main flow（AI 本身）对每个 func 渲染测试点 MD——**不派 subagent**：

1. **读 JSON 详情**（`Read` 工具）
2. **读 spec 和 template**（`Read` 工具）
3. **分析页面**（按下方"Web 补充原则"和"分析原则"）
4. **渲染 Markdown**（参考 testpoint-template.md）
5. **写入文件**（`Write` 工具）：`AI-测试点分析/<模块路径>/<功能名>.md`（UTF-8）

### 第五步：公共模块（可选）

如批次中有 2+ 页面共享相似顶部导航、侧边栏、登录状态入口，main flow 生成 `AI-测试点分析/全局通用功能/00_全局通用模块.md`。

### 第六步：汇总报告

## 思维导图格式规则

- 每个最终生成的 Markdown 文件必须以以下格式说明开头：

```markdown
---
convert: mindmap
---
```

- 只使用一个 `#` 一级标题作为中心主题
- 使用 `##`、`###`、`####` 表达分支层级
- 使用 `-` 列表表达叶子节点
- 不使用 Markdown 表格作为主要结构
- 每行尽量是一个可读节点
- 测试点必须拆成"操作""数据""预期""覆盖元素"等子节点
- 每个测试点必须有"操作"和"预期"

## 分析原则

- 只写当前 `func` 的专属测试点
- 顶部导航、侧边栏、登录态入口、页脚等公共元素只引用 `00_全局通用模块.md`，不在每个页面重复展开
- 不把其他业务功能写入当前文档
- 不臆造后端接口、数据库、具体路由实现
- 优先从 `interface_desc` / `layout_desc` / `elements_desc` 提取测试点，结合截图判断
- 对登录、注册、搜索、表单类页面，必须覆盖空值、格式错误、长度边界、重复提交、密码显示规则、网络异常或服务异常提示
- 对列表、分页、筛选、排序类页面，必须覆盖空列表、单页、多页、翻页边界、筛选无结果、组合筛选、数据格式
- 对上传、下载、支付、删除等高风险操作，必须覆盖权限、确认弹窗、失败回滚、重复操作、异常中断

### Web 补充原则

- 必须覆盖浏览器兼容：Chrome / Firefox / Safari / Edge 主流版本
- 必须覆盖响应式布局：桌面（1920×1080）/ 平板（768×1024）/ 手机（375×667）三种视口
- 必须覆盖键盘操作：Tab 键焦点顺序、Enter 提交、Esc 关闭模态框、方向键导航
- 必须覆盖输入校验：HTML5 input type（email/url/tel/number/date）校验、required 属性、maxlength
- 必须覆盖富交互：下拉菜单联动、日期范围选择、富文本编辑器、文件上传/下载、拖拽排序
- 必须覆盖表单：提交前校验、提交后反馈（toast/alert/页面跳转）、重置按钮、必填项标记
- 必须覆盖网络与异常：飞行模式、弱网/断网重连、API 失败重试、429 限流
- 必须覆盖生命周期：页面刷新、关闭重开、返回按钮、URL 参数保留
- 必须覆盖安全：XSS 注入、CSRF、SQL 注入、暴力破解、敏感信息脱敏
- 必须覆盖性能：首屏加载时间、列表分页加载、滚动懒加载
- 必须覆盖无障碍：屏幕阅读器、键盘导航、ARIA 属性、颜色对比度
- 必须覆盖多端一致：与移动端/桌面端的差异点
- 平台差异需在测试点中标注：例如"鼠标悬停""右键菜单""键盘快捷键""浏览器前进/后退"等 Web 独有形态

## 全局公共模块策略

- 如果指定批次中有 2 个及以上页面共享相似顶部导航、侧边栏、登录状态入口、页脚，生成 `AI-测试点分析/全局通用功能/00_全局通用模块.md`
- 如果只分析单个页面，可以在页面文档中写"全局公共模块：本批次未单独生成，按当前页面 JSON 识别为公共区域"，但不要展开大量公共测试点
- 公共模块的"登录状态变化"必须覆盖未登录/已登录两种态；Web 端额外覆盖多账号切换、Cookie/Clear-Site-Data 清空
- 页面文档引用公共模块时，按页面文档位置计算到 `AI-测试点分析/全局通用功能/00_全局通用模块.md` 的相对路径
- 如果跨多个模块生成文档，仍然只维护项目级的公共模块文档，不要在每个模块目录重复生成公共模块

## ⚠️ Markdown 格式硬性要求

参见通用格式要求（同 case-gen）。重点：
- `##` 标题井号后必须留半角空格
- 列表 `-` / `1.` 后必须留半角空格
- 表格 `|` 两侧必须有空格
- 代码块用三反引号包围
- 生成后用 `grep -nE '^#{1,6}[^# ]' <file>` 复核

## 注意事项

1. **必须指定批次号**——禁止自动跑 `--list-batches`
2. **本技能无 subagent**——main flow 直接渲染每个 func 的 MD
3. **重跑同批次 = 直接覆盖**——同源数据产生同样分析
4. **整批共用 scanner 一次调用**
5. **公共模块按需生成**
6. **每个 func 一个 MD**
7. **截图相对路径正确**
