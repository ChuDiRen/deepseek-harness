# BigBear Android TestPoint（单批次版）

## 核心能力

基于 `AI-信息采集/{批次号}/{模块路径}/` 中的视觉分析 JSON、页面截图和视觉识别结果，生成可导入思维导图工具的 Markdown 测试点分析文档。覆盖安卓（Android 设备）UI。

适配工具包括 XMind、幕布、Markmap、ProcessOn、GitMind 等按 Markdown 标题和列表生成节点的工具。

**本技能每次处理一个明确的批次**——不主动扫描整个工作空间找批次。

## 产物模板与规范

本技能有明确输出物：安卓页面测试点分析 Markdown 与全局公共模块 Markdown。执行前必须按需读取：

- `references/testpoint-template.md`：安卓页面测试点与全局公共模块的最终 Markdown 模板
- `references/testpoint-spec.md`：批次读取、分析边界、输出规则、公共模块策略和自检规范

硬性要求：最终产物结构以 template 为准，生成行为和质量要求以 spec 为准。

## 工作目录约定

```
{工作空间}/                          ← 项目根目录
├── AI-信息采集/{批次号}/{模块路径}/      ← 输入
│   ├── json/dom_001.json
│   └── img/screenshot_001.png
├── AI-测试点分析/{模块路径}/            ← 输出（本技能写入）
│   ├── <功能名>.md
│   └── ...
├── AI-测试点分析/全局通用功能/
│   └── 00_全局通用模块.md              ← 公共模块（本技能在需要时生成）
└── AI-测试用例/                       ← 由 case-gen 写入
    └── {模块路径}/<功能名>_测试用例.md
```

## 触发条件

满足其一：
- 用户说"分析安卓测试点" / "生成安卓测试点" / "安卓UI测试点分析" + **明确提供批次号**
- 用户提供具体 JSON 文件路径

## 执行流程

### 第一步：判断用户是否指定了具体批次

检查用户输入是否包含：
- 批次号（如 `20260609-223046`、`20260606-153022`）
- 批次目录路径（如 `AI-信息采集/20260609-223046/`）
- 具体 JSON 文件路径

如果**指定了** → 直接进入第三步。
如果**未指定** → 询问用户：
- "请提供要分析的批次号（格式如 `20260609-223046`），或说'扫一下批次'让我列出所有可用批次。"

### 第二步：（可选）扫批次

**仅当用户明确说"扫一下批次"/"列出批次"/"有哪些批次"等** 才跑：

```bash
python .claude/skills/bigbear-android-testpoint/scripts/scanner.py --list-batches
```

把输出展示给用户，让他们选。

> **默认**不跑这一步。用户给批次号就直接处理。

### 第三步：scanner.py 解析指定批次

用户确认批次后，跑：

```bash
python .claude/skills/bigbear-android-testpoint/scripts/scanner.py --batch "<批次号>" --json
```

scanner 输出：
- `batches[*].features[*]`：每个 feature（页面）的 JSON 列表、截图数量、输出目录
- 每个 JSON 解析后的 `module`、`func`、`desc`、`page_url`、`page_title`、`img` 路径

> scanner 会自动定位 `AI-信息采集/`：先在当前目录找，找不到向上一级找。

### 第四步：main flow 直接处理每个 func

Main flow（AI 本身）对每个 func 渲染测试点 MD——**不派 subagent**：

1. **读 JSON 详情**（`Read` 工具读 JSON 文件）
2. **读 spec 和 template**（`Read` 工具）：
   - `references/testpoint-spec.md`（分析边界、输出规则、公共模块策略）
   - `references/testpoint-template.md`（最终 Markdown 结构）
3. **分析页面**（按下方"安卓补充原则"和"分析原则"）
4. **渲染 Markdown**（参考 testpoint-template.md）：
   - 文件开头必须有 `--- convert: mindmap ---` 格式说明
   - 一级标题：`# <功能名>`
   - 多级分支：`##`、`###`、`####` + `-` 列表
5. **写入文件**（`Write` 工具）：`AI-测试点分析/<模块路径>/<功能名>.md`（UTF-8）
   - 父目录不存在则用 `Bash` 工具 `mkdir -p` 创建

### 第五步：公共模块（可选）

如果批次中有 2+ 页面共享相似状态栏、TabBar、登录状态入口、侧边栏或底部导航，main flow 生成 `AI-测试点分析/全局通用功能/00_全局通用模块.md`。

### 第六步：汇总报告

处理完所有 func 后，main flow 输出汇总报告。

## 思维导图格式规则

- 每个最终生成的 Markdown 文件必须以以下格式说明开头：

```markdown
---
convert: mindmap
---
```

- 格式说明后再写 `#` 一级标题
- 只使用一个 `#` 一级标题，作为中心主题
- 使用 `##` 作为一级分支
- 使用 `###` 和 `####` 作为下级分支
- 使用 `-` 列表表达叶子节点
- 不使用 Markdown 表格作为主要结构
- 不使用大段说明文字；每行尽量是一个可读节点
- 测试点必须拆成"操作""数据""预期""覆盖元素"等子节点
- 每个测试点必须有"操作"和"预期"

## 分析原则

- 只写当前 `func` 的专属测试点
- 状态栏、TabBar、底部导航、侧边栏、登录态入口等公共元素只引用 `AI-测试点分析/全局通用功能/00_全局通用模块.md`，不在每个页面重复展开
- 不把其他业务功能写入当前文档。例如分析"登录"时，不展开"全部作品""充值""个人中心"的业务测试点，只把它们识别为全局导航入口
- 不臆造后端接口、数据库、具体路由实现。JSON 中有 URL 时可作为页面来源记录；测试点里只描述跳转目标
- 优先从 `interface_desc` / `layout_desc` / `elements_desc` 提取测试点，结合截图判断
- 对登录、注册、搜索、表单类页面，必须覆盖空值、格式错误、长度边界、重复提交、密码显示规则、网络异常或服务异常提示
- 对列表、分页、筛选、排序类页面，必须覆盖空列表、单页、多页、翻页边界、筛选无结果、组合筛选、数据格式
- 对上传、下载、支付、删除等高风险操作，必须覆盖权限、确认弹窗、失败回滚、重复操作、异常中断

### 安卓补充原则

- 必须覆盖安卓系统能力：状态栏、信号/Wi-Fi、电量、通知中心、控制中心（快速设置）、横竖屏切换、暗黑/亮色模式、字体大小、勿扰模式、权限弹窗（相机/相册/位置/通讯录/麦克风/通知/电话 等）
- 必须覆盖安卓系统交互：物理返回/手势返回/导航条返回、Home 键、多任务切换、应用切换、杀进程重启恢复、后台切前台、长按、平台特有手势
- 必须覆盖输入与软硬件键盘：中文/英文/数字/符号、输入法切换、表情、语音输入、自动填充、密码管理器、自动联想、复制粘贴
- 必须覆盖网络与异常：飞行模式、弱网/断网重连、切换 Wi-Fi/蜂窝、VPN、低延迟场景、推送（厂商通道/FCM）与本地通知
- 必须覆盖生命周期：冷启动、热启动、首次安装、升级覆盖安装、清除数据、登出登入、跨设备同步、消息推送点击进入指定页
- 必须覆盖安全与隐私：截屏限制、指纹/人脸/数字密码、生物识别失败回退、敏感信息遮罩、后台脱敏、权限运行时申请
- 必须覆盖多端一致：与 H5/Web/桌面端的差异点
- 平台差异需在测试点中标注：例如"桌面小组件""Material You 主题""后台管理""省电优化""多窗口分屏""画中画"等 Android 独有形态

## 全局公共模块策略

- 如果指定批次中有 2 个及以上页面共享相似状态栏、TabBar、登录状态入口、侧边栏或底部导航，生成 `AI-测试点分析/全局通用功能/00_全局通用模块.md`
- 如果只分析单个页面，可以在页面文档中写"全局公共模块：本批次未单独生成，按当前页面 JSON 识别为公共区域"，但不要展开大量公共测试点
- 公共模块的"登录状态变化"必须覆盖未登录/已登录两种态；安卓端额外覆盖多账号切换
- 页面文档引用公共模块时，按页面文档位置计算到 `AI-测试点分析/全局通用功能/00_全局通用模块.md` 的相对路径
- 如果跨多个模块生成文档，仍然只维护项目级的公共模块文档，不要在每个模块目录重复生成公共模块

## ⚠️ Markdown 格式硬性要求（必读·防止生成出错）

参见通用格式要求（同 case-gen）。重点：
- `##` 标题井号后必须留半角空格
- 列表 `-` / `1.` 后必须留半角空格
- 表格 `|` 两侧必须有空格
- 代码块用三反引号包围
- 生成后用 `grep -nE '^#{1,6}[^# ]' <file>` 复核

## 注意事项

1. **必须指定批次号**——禁止自动跑 `--list-batches`；除非用户明确说"扫一下批次"或"列出批次"
2. **本技能无 subagent**——main flow（AI 本身）直接渲染每个 func 的 MD
3. **重跑同批次 = 直接覆盖**——同源数据产生同样分析；要保留历史先 `cp` 一份
4. **整批共用 scanner 一次调用**——一次 `--batch` 跑完所有 func
5. **用户自挑 func**——如果用户只关心某个 func，让他指定"只分析 登录 功能"
6. **公共模块按需生成**——2+ 共享元素才生成
7. **每个 func 一个 MD**——同 func 多个 JSON 合并分析
8. **截图相对路径正确**——页面文档中的图片路径相对位置要算对

```
bigbear-{platform}-case-generator →  AI-测试点分析 → AI-测试用例 MD
```
