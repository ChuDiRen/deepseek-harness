# AI-安卓 UI 测试点分析 Markdown 模板

本文档只定义 `bigbear-android-testpoint` 的最终输出结构。分析原则、批次规则、公共模块策略和自检规则见 `testpoint-spec.md`。

## 页面测试点文件命名

`{功能名}.md`

示例：`登录.md`

## 页面测试点文档模板

```markdown
---
convert: mindmap
---

# 【<功能名>】测试点分析

## 基础信息

- 批次号：<batch>
- 平台：安卓
- 功能名称：<功能名>
- 前置条件：<未登录/已登录/具备权限/无特殊前置条件>

## 页面来源

- 采集目录：<AI-信息采集/<批次号>/<模块路径>/>
- 人工描述：<desc 字段，未提供则写"未提供">
- 界面整体描述：<interface_desc，未提供则写"未提供">
- 布局描述：<layout_desc，未提供则写"未提供">
- JSON 文件：<json相对路径>
- 截图文件：<screenshot相对路径>
- 页面截图：<从本文档到截图的相对路径>

## 全局公共模块

- 引用：<到 AI-测试点分析/全局通用功能/00_全局通用模块.md 的相对路径>
- 处理规则：本文档只分析当前功能专属区域
- 公共区域：<状态栏/TabBar/侧边栏/底部导航/无>

## 页面元素说明

### <元素名称>

- 类型：自然语言描述加控件类型。例如：按钮(button)、菜单项(menu)、列表项(list)、输入框(input)
- 示例：<elements_desc 中的描述或可见文案>
- 可操作：是/否
- 作用：<业务含义>

## 功能测试点

### <功能分组>

#### <测试点名称>

- 操作：<用户操作，含键盘/鼠标/手势>
- 数据：<测试数据，没有则写"无特殊数据">
- 预期：<界面变化、提示、跳转目标或数据变化>
- 覆盖元素：<相关页面元素>

## 状态测试点

### 初始状态

- 触发：首次进入页面
- 预期：页面核心元素完整显示，状态栏/导航栏处理符合平台规范

### 交互状态

- 触发：点击、双击、长按、悬停、手势等交互
- 预期：控件状态、样式或提示正确变化

### 生命周期

- 触发：<冷启动/热启动/杀进程/后台切前台/锁屏解锁>
- 预期：<页面状态、滚动位置、表单内容、登录态符合预期>


## 边界条件

### 空值校验

- 数据：必填项为空
- 操作：提交表单
- 预期：显示明确校验提示，阻止提交

### 系统异常

- 触发：断网/服务异常/磁盘满
- 预期：显示离线/重试/错误提示，行为可恢复

## 业务跳转

### <跳转入口>

- 操作：点击 <入口名称>
- 预期：跳转到 <目标页面名称>
- 说明：不臆造具体路由，仅记录可见跳转目标
```
