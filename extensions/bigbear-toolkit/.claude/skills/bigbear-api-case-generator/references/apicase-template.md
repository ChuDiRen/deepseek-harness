# API 接口测试用例 Markdown 模板

本文档描述 `bigbear-api-case-generator` 最终输出的单接口用例 Markdown 文件结构。生成策略、覆盖范围、断言写法见 `testcase-spec.md` 与 `SKILL.md`。

## 文件命名

`<interface_name>_测试用例_<YYYYMMDDHHMMSS>.md`

- `interface_name` 来自接口 MD 的 `### 接口名称` 字段
- 例：接口 MD 标题 `# GET /book/listClickRank` → 文件名 `GET_book_listClickRank_测试用例_20260610150000.md`
- `YYYYMMDDHHMMSS` = 主流程在派发时生成的 14 位时间戳，**整批共用同一个**
- 路径：`AI-测试用例/{module}/{interface_name}_测试用例_<TIMESTAMP>.md`（`{module}` = 接口 MD 的父目录名）

## 文件模板

```markdown
---
convert: apitest
batch: <批次号，如 20260609-223046>
interface_key: <METHOD> <PATH>[?param1=&param2=...]
interface_name: <接口名，从 MD 的 ### 接口名称 读取>
interface_file: <相对工作空间的接口 MD 路径>
case_count: <本文件用例总数>
generated_at: <本次生成时间，ISO 格式 YYYY-MM-DDTHH:MM:SS>
---

## <场景名称>

### 用例信息

| 字段 | 内容 |
| ---- | ---- |
| 用例编号 | <uuid.uuid4().hex 生成的 32 位无横杠 hex> |
| 测试标题 | <场景名称> |
| 前置条件 | <前置条件> |
| 优先级 | <P0/P1/P2/P3> |

### 请求信息

| 项目 | 内容 |
| ---- | ---- |
| 请求URL | {{ URL }}<请求路径> |
| 请求方法 | <GET/POST/PUT/DELETE/PATCH> |

### 请求头

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| <请求头名称> | <请求头值> | <请求头说明> |

### URL参数

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| <参数名> | <{{ 测试数据占位符 }}> | <参数说明> |

### 请求体参数

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| <参数名> | <{{ 测试数据占位符 }}> | <参数说明> |

### 预期结果

- 响应状态码：<HTTP 状态码>
- 响应格式：<响应格式>
- <业务断言 1>
- <业务断言 2>
```

## 历史版本

每次生成都是**独立新文件**，文件名带时间戳。同一接口多次生成会有多个文件共存：

```
AI-测试用例/用户模块/
├── 用户登录_测试用例_20260610150000.md     ← 第一次生成
├── 用户登录_测试用例_20260610160000.md     ← 第二次生成
└── 用户登录_测试用例_20260610170000.md     ← 第三次生成
```

- 历史文件**不会被本技能读取、修改或删除**
- 由用户自行挑选保留哪个版本（通常用最新一份）
- 不需要的旧文件可手工 `rm`

## 填写规则

- 每个用例文件**只**包含 `frontmatter` 和 `## 详细用例` 两个部分。**禁止生成"用例总览"章节**。
- `interface_key` 写在 frontmatter，**不要**单独写表格或章节。
- 多条用例时，每条用例追加一个 `## <场景名>` 详细段落。
- 无请求头、无请求参数、无请求体时保留表格标题，预留一行 `| 无 | 无 | ... |`，不要删除整节。
- 动态测试数据统一使用 Jinja2 风格占位符：`{{ 变量名 }}`，例如 `{{ 正确账号 }}`、`{{ 有效Token }}`。
- 标题井号后必须留一个半角空格：`## 场景` 而非 `##场景`。
- 列表 `-` 后必须留一个半角空格：`- 业务断言` 而非 `-业务断言`。

## Markdown 渲染硬性约束（防反引号污染）

**禁止用反引号（`` ` ``）包裹纯文本字段**——反引号会让 markdown 渲染成代码块，导致：

- `请求URL` 行的 `{{ URL }}/user/login` 变成 `` `{{ URL }}/user/login` ``，运行时引擎无法识别 Jinja2 模板变量
- `请求体参数` 的 `<{{ 测试数据占位符 }}>` 同理
- `预期结果` 中的 URL/参数值被代码字体显示

**反例**（禁止）：

```markdown
| 请求URL | `{{ URL }}/user/login` |         ← ❌ URL 被反引号包
| 参数名 | `<{{ 测试数据占位符 }}>` |       ← ❌ 占位符被反引号包
```

**正例**（正确）：

```markdown
| 请求URL | {{ URL }}/user/login |            ← ✅ 纯文本
| 参数名 | <{{ 测试数据占位符 }}> |          ← ✅ 占位符尖括号保留
```

**特殊说明**：

- 文档**示例**中的 `{{ 变量名 }}` 用反引号包没问题（如 `\`{{ URL }}\` 这种是说明语法，不是模板行）
- 实际写入 case MD 的**模板行**（会被 AI 复制到每条用例里）必须**保持纯文本**
- JSONPath / 正则 在 `预期结果` 文本中可用反引号包（如 `（JSONPath: \`$.data.id\`）`，这是代码引用语境）

**额外防御**：

- 如果接口 MD 里的字段值自带反引号，main flow 应**剥除**或**转义**反引号，**不要**让它进 case MD
- 文件名也不应含反引号
