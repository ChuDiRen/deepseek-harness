# BIGBEAR Android Case Generator - 测试点转测试用例技能（单文件版）

## 核心能力

基于单个安卓测试点分析文档（MD格式）生成可直接执行的安卓功能测试用例：

- 解析测试点分析文档中的功能测试点、状态测试点、边界条件、安卓补充测试点
- 拆解测试点为具体可执行的测试用例（含具体测试数据）
- 生成带测试步骤、预期结果、前置条件的标准化 Markdown 用例
- 自动使用占位符表示测试数据
- 覆盖安卓特有控件：系统返回手势、长按、生物识别、推送、权限弹窗、桌面小组件、Shortcut、Material You

## 支持平台

| 平台 | 平台标记 | 安卓控件示例 |
| --- | --- | --- |
| 安卓 | 安卓 | 系统返回手势、长按、生物识别、推送、权限弹窗、桌面小组件、Shortcut、Material You |

> 平台信息应已在测试点分析文档的"基础信息"中标注；main flow 生成用例时把平台信息写入"用例信息.平台"字段。

## 产物模板与规范

本技能有明确输出物：安卓功能测试用例 Markdown 文件。执行前必须读取：

- `references/testcase-template.md`：最终测试用例 Markdown 模板
- `references/testcase-spec.md`：测试点拆解、测试设计、步骤写法、优先级和编号规则

## 工作目录约定

```
{工作空间}/
├── AI-测试点分析/<module>/<功能名>.md     ← 测试点分析（输入）
└── AI-测试用例/<module>/                 ← 用例（输出）
    └── <功能名>_测试用例_<YYYYMMDDHHMMSS>.md
```

**模块路径** = 测试点 MD 的**父目录名**（即 `<module>`）。

## 触发条件

满足其一：
- 用户说"生成测试用例" / "用例生成" / "生成安卓端用例" / "生成安卓用例"
- 用户提供安卓测试点分析文档路径
- 用户在测试点分析文档目录下说"基于这些文档生成用例"

## 执行流程

### 第一步：判断用户是否指定了具体 MD

检查用户输入是否包含：
- 具体功能名（如"登录"、"Banner"）
- 具体 MD 路径（如 `AI-测试点分析/首页模块/登录.md`）

如果**指定了** → 直接进入第三步，定位该 MD，跳过扫描。
如果**未指定** → 进入第二步扫描询问。

### 第二步：扫描 + 询问（仅在未指定 MD 时）

Main flow 扫描 `AI-测试点分析/**/*.md`，按 module 分组输出清单。

询问用户：
- 单一模块 / 多个模块 / 单个 MD / 全部

**默认**：每次只处理一个模块。

### 第三步：生成时间戳

Main flow 生成一个**整批共用**的 14 位时间戳 `YYYYMMDDHHMMSS`（例：`20260610150000`）。

### 第四步：main flow 直接处理每个 MD

Main flow（AI 本身）对每个测试点 MD 执行以下动作——**不派发 subagent**：

1. **读取测试点 MD**（`Read` 工具）
2. **读取参考规范**：
   - `references/testcase-template.md`（Markdown 结构、字段）
   - `references/testcase-spec.md`（测试点拆解、步骤写法、优先级）
3. **拆解测试点 → 测试用例**（按下方"平台特有规范"章节）
4. **渲染完整 Markdown**（参考 testcase-template.md）：
   - 文件标题：`# <模块路径>_<功能名> - AI-测试用例`
   - 一级 `convert: uitest` frontmatter
   - 多条 `## <测试标题>` 段落，每段含 ### 用例信息 / ### 测试步骤 / ### 预期结果
5. **写入文件**（`Write` 工具）：`AI-测试用例/<module>/<功能名>_测试用例_<TIMESTAMP>.md`（UTF-8）
   - 如 `AI-测试用例/<module>/` 不存在则用 `Bash` 工具 `mkdir -p` 创建

### 第五步：汇总报告

处理完所有 MD 后，main flow 输出汇总报告。

## 平台特有规范（安卓）

### 测试点 → 测试用例拆解原则

1. **功能测试点**：
   - 每个测试点拆解为 1-N 条具体测试用例
   - 正向测试点：至少生成 1 条正常流程用例
   - 反向测试点：生成异常校验用例（空值、格式错误、边界值）

2. **状态测试点**：
   - 加载状态 → 转化为"页面加载验证"用例
   - 交互状态 → 转化为"交互操作"用例（如点击、双击、长按、手势、滑动）
   - 窗口生命周期 → 转化为"最小化/最大化/关闭/多窗口切换"用例

3. **边界条件测试**：
   - 直接转化为测试用例，测试数据使用边界值

4. **安卓补充测试点**：
   - 系统能力：状态栏、信号/Wi-Fi、电量、通知中心、横竖屏、暗黑/亮色模式、权限弹窗
   - 系统交互：物理返回/手势返回/导航条返回、Home 键、多任务切换、应用切换、长按
   - 输入能力：中文/英文/数字、输入法切换、表情、语音、自动填充、复制粘贴
   - 网络与异常：飞行模式、弱网/断网重连、Wi-Fi/蜂窝切换、VPN、推送
   - 生命周期：冷启动、热启动、杀进程恢复、登出登入
   - 离线与异常：断网、服务异常、磁盘满、读写失败、权限拒绝
   - 多端差异：与 H5/桌面端的差异点
   - 平台独有形态：见各平台补充项
   - 以上每条测试点都必须拆解为独立的测试用例，必要时覆盖"操作"+"预期"两段

### 测试数据说明

- 测试数据直接在测试步骤中使用占位符表示，如：`{{ 用户手机号 }}`、`{{ 登录密码 }}`
- 静态数据（格式校验、边界值）直接写具体值，无需单独列出

### 测试步骤格式

强制使用操作步骤格式：`操作 "字段名"控件类型 操作值`

- **操作**：置于步骤最前；输入、选择、点击、勾选、清空、滑动、左滑、右滑、上滑、下滑、双击、长按、系统返回、Home 键、Face ID、指纹、启动、按下 等
- **字段名**：控件的标签文字或标识，使用半角双引号包裹
- **控件类型**：紧跟在引号外；输入框、密码框、按钮、单选框、复选框、下拉选项、系统返回手势、长按、生物识别、推送、权限弹窗、桌面小组件、Shortcut、Material You 等
- **操作值**：具体操作内容，使用 `{{ 占位符 }}` 表示动态数据；点击等无值操作可省略，安卓独有控件如需占位也可省略

**示例（安卓登录页面）**：
1. 输入 "账户/手机号"输入框 {{ 用户手机号 }}
2. 输入 "密码"密码框 {{ 登录密码 }}
3. 输入 "验证码"输入框 {{ 验证码 }}
4. 点击 "登入系统"按钮
5. 按下 Ctrl+Enter 组合键
6. 双击 "窗口标题栏"

**示例（安卓菜单栏操作）**：
1. 启动应用
2. 点击 "文件"菜单项
3. 点击 "打开"菜单项
4. 输入 "文件名"输入框 {{ 文件路径 }}
5. 点击 "打开"按钮

**示例（安卓侧边栏导航）**：
1. 点击 "个人中心"侧边栏按钮
2. 点击 "账号设置"列表项

### 预期结果具体化

| 测试点写法 | 转化为具体预期结果 |
|---------|--------------|
| 登录成功 | 提示"登录成功"，跳转至首页，顶部导航显示用户昵称 |
| 提示输入手机号 | 手机号输入框下方显示红字"请输入手机号码" |
| 系统返回 | 退出当前窗口或返回上一级，未保存内容弹出"是否保存"提示 |
| 关闭主窗口 | 弹出"确认退出"提示，点击确认后进程退出；点击取消则不退出 |
| 弱网提示 | 显示"网络异常，请检查网络设置"toast，自动触发重连 |
| 离线提示 | 显示"网络异常，请检查网络设置"提示，可重试或查看本地缓存 |
| 生物识别失败 | 弹出 Face ID/Touch ID/指纹失败提示，3 次失败后回退到密码登录 |

## 测试用例编号

每条用例使用 `uuid.uuid4().hex`（**32 位无横杠 hex 字符串**）作为唯一编号，**main flow 直接生成**。

> 不要用 `str(uuid.uuid4())`（36 位带横杠），也不要对带横杠字符串手动 `replace('-', '')`。
> 
> 生成方式：main flow 自行在每条用例的"用例编号"字段填一个 UUID；无需额外 Bash 命令。

## ⚠️ Markdown 格式硬性要求（必读·防止生成出错）

生成 Markdown 文档时，**最常出现的格式错误**集中在以下几点。请在写入文件**之前**逐条自检，写入**之后**用 grep 复核一遍：

### 1. 标题井号后必须有一个半角空格

- ✅ 正确：`## 测试目的`、`### 用例 1：正常登录`
- ❌ 错误：`##测试目的`、`###用例 1：正常登录`（井号后没空格，渲染器会把整行当成普通段落，思维导图工具会丢节点）
- **正则自检**（任意命中即说明有错）：`^#{1,6}[^# ]`

### 2. 列表符号后必须有一个半角空格

- ✅ 正确：`- 操作：点击登录按钮`、`* 数据：用户名为空`、`1. 启动应用`
- ❌ 错误：`-操作：点击登录按钮`、`*数据：用户名为空`、`1.启动应用`
- **正则自检**：`^[ \t]*[-*+][^ ]` 或 `^[ \t]*[0-9]+\.[^ ]`

### 3. 表格分隔符 `|` 两侧必须有空格（除两端外）

- ✅ 正确：`| 字段名 | 值 | 说明 |`、`| ---- | ---- | ---- |`
- ❌ 错误：`|字段名|值|说明|`

### 4. 代码块必须用三反引号包围，且开头需指定语言

- ✅ 正确：` ```json ` ... ` ``` `、` ```bash ` ... ` ``` `、` ```text ` ... ` ``` `

### 5. 段落之间必须有空行

- ✅ 正确：标题/段落/列表/表格之间各空一行

### 6. 生成后强制自检

```bash
# 检查所有标题井号后是否都有空格(应该没有输出)
grep -nE '^#{1,6}[^# ]' <文件路径>
# 检查所有 - 列表项后是否都有空格
grep -nE '^[ \t]*[-*+][^ ]' <文件路径>
# 检查所有数字列表项后是否都有空格
grep -nE '^[ \t]*[0-9]+\.[^ ]' <文件路径>
```

**任一命令有输出 → 必须修正后重写文件**。

## 注意事项

1. **可指定单 MD 生成**——用户说"XXX 的用例"时直接处理该 MD，跳过扫描
2. **每次独立**——不读、不改、不合并已有用例文件
3. **整批共用一个时间戳**——main flow 一次生成，所有 MD 用同一个 YYYYMMDDHHMMSS
4. **同 MD 多版本共存**——文件名带时间戳，同一测试点文档多次生成会有多个文件
5. **用户自己挑版本**——历史文件由用户决定保留哪个
6. **每个测试点文档一个 case MD**——一个 case MD 只含一个功能的用例
7. **模块从测试点 MD 父目录推**——不维护模块映射表
8. **测试数据使用占位符**：动态数据使用 `{{ 占位符 }}` 格式；静态数据（格式校验、边界值）可直接写具体值
9. **预期结果必须具体**：禁止"提示正确"等模糊描述，必须写具体现象（toast 文案、跳转路径、控件状态、生物识别提示 等）
10. **"字段名"控件类型 操作 操作值格式**：测试步骤必须使用此格式
11. **不要推测**：只使用文档中已有的信息，不要自行添加文档未描述的测试点
12. **平台信息必填**：用例标题中"AI-测试用例"是统一的；平台靠"用例信息.平台"字段（固定填"安卓"）区分
13. **安卓控件必须覆盖**：对登录、注册、表单、支付等高敏感页面，必须补充系统返回、生物识别、推送、权限弹窗、横竖屏、生命周期用例

## 与其他技能的关系

```
bigbear-{platform}-testpoint        →  生成测试点分析文档
bigbear-{platform}-case-generator  →  单个测试点 MD → case 文件（当前技能，main flow 直接处理，无 subagent）
bigbear-{platform}-test-runner     →  执行用例（不在本技能范围）
```
