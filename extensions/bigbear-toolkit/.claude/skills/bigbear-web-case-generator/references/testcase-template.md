# Web 测试用例 Markdown 模板

本文档只定义 `bigbear-web-case-generator` 的最终测试用例文件结构。测试设计、拆解、优先级和步骤写法见 `testcase-spec.md`。

## 文件命名

`<功能名>_测试用例_<YYYYMMDDHHMMSS>.md`

示例：`登录_测试用例_20260610150000.md`

- `YYYYMMDDHHMMSS` = main flow 在生成时产生的 14 位时间戳
- 时间戳保证多次生成同名测试点 MD 时**不撞文件名**

## 文件模板

```markdown
---
convert: uitest
---

# <模块路径>_<功能名> - AI-测试用例

## <测试标题>

### 用例信息

| 字段 | 内容 |
| ---- | ---- |
| 用例编号 | <用例编号> |
| 用例名称 | <测试标题> |
| 优先级 | <P0/P1/P2/P3> |
| 前置条件 | <前置条件> |

### 测试步骤

1. "<字段名>"<控件类型> <操作> <操作值>
2. "<字段名>"<控件类型> <操作> <操作值>
3. 点击"<按钮名>"按钮

### 预期结果

- 具体页面提示、跳转
- 控件状态、数据变化或业务结果
- < 业务断言1 >
- < 业务断言2 >
```

## 多用例写法

- 同一文件内可以包含多个 `## <测试标题>`。
- 每条用例都必须包含字段表、测试步骤、预期结果。
- 文件顶部的 `convert: uitest` 只出现一次。
- 不保留 `<...>` 占位；
- 动态测试数据使用 `{{ 参数变量名 }}` 这类jinjia2模板引擎占位符。
- 模块路径含多层时(如 `用户模块/登录注册`)，一级标题里用 `/` 保留原层级，或用 `_` 拼接成 `用户模块_登录注册_登录` 也可，保持单个文件内一致即可。
