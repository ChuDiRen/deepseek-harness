# BIGBEAR Web Case Generator - Web 测试点转测试用例技能（单文件版）

## 核心能力

基于单个 Web 测试点分析文档（MD格式）生成可直接执行的 Web 功能测试用例：

- 解析测试点分析文档中的功能测试点、状态测试点、边界条件
- 拆解测试点为具体可执行的测试用例（含具体测试数据）
- 生成带测试步骤、预期结果、前置条件的标准化 Markdown 用例
- 自动使用占位符表示测试数据
- 覆盖 Web 通用控件：表单、按钮、模态框、下拉菜单、日期选择器、富文本编辑器、文件上传

## 支持平台

| 平台 | 平台标记 | Web 控件示例 |
| --- | --- | --- |
| Web | Web | 表单、按钮、模态框、下拉菜单、日期选择器、富文本编辑器、文件上传 |

> 平台信息应已在测试点分析文档的"基础信息"中标注；Web 模板无"平台"字段，平台信息放在文件标题里。

## 产物模板与规范

本技能有明确输出物：Web 功能测试用例 Markdown 文件。执行前必须读取：

- `references/testcase-template.md`：最终测试用例 Markdown 模板
- `references/testcase-spec.md`：测试点拆解、测试设计、步骤写法、优先级和编号规则

## 工作目录约定

```
{工作空间}/
├── AI-测试点分析/<module>/<功能名>.md     ← 测试点分析（输入）
└── AI-测试用例/<module>/                 ← 用例（输出）
    └── <功能名>_测试用例_<YYYYMMDDHHMMSS>.md
```

**模块路径** = 测试点 MD 的**父目录名**（即 `<module>`）。模块路径含多层时（如 `用户模块/登录注册`），一级标题里用 `/` 保留原层级，或用 `_` 拼接成 `用户模块_登录注册_登录` 也可，保持单个文件内一致即可。

## 触发条件

满足其一：
- 用户说"生成测试用例" / "用例生成" / "生成 Web 用例"
- 用户提供 Web 测试点分析文档路径
- 用户在测试点分析文档目录下说"基于这些文档生成用例"

## 执行流程

### 第一步：判断用户是否指定了具体 MD

检查用户输入是否包含：
- 具体功能名（如"登录"、"新建工单"）
- 具体 MD 路径（如 `AI-测试点分析/首页模块/登录.md`）

如果**指定了** → 直接进入第三步，定位该 MD，跳过扫描。
如果**未指定** → 进入第二步扫描询问。

### 第二步：扫描 + 询问（仅在未指定 MD 时）

Main flow 扫描 `AI-测试点分析/**/*.md`，按 module 分组输出清单。

询问用户：
- 单一模块 / 多个模块 / 单个 MD / 全部

**默认**：每次只处理一个模块。

### 第三步：生成时间戳

Main flow 生成一个**整批共用**的 14 位时间戳 `YYYYMMDDHHMMSS`（例：`20260610150000`）。

### 第四步：main flow 直接处理每个 MD

Main flow（AI 本身）对每个测试点 MD 执行以下动作——**不派发 subagent**：

1. **读取测试点 MD**（`Read` 工具）
2. **读取参考规范**：
   - `references/testcase-template.md`（Markdown 结构、字段）
   - `references/testcase-spec.md`（测试点拆解、步骤写法、优先级）
3. **拆解测试点 → 测试用例**（按下方"平台特有规范"章节）
4. **渲染完整 Markdown**（参考 testcase-template.md）：
   - 文件标题：`# <模块路径>_<功能名> - AI-测试用例`（Web 模板无"平台"字段，平台标记在标题中）
   - 一级 `convert: uitest` frontmatter
   - 多条 `## <测试标题>` 段落，每段含 ### 用例信息 / ### 测试步骤 / ### 预期结果
5. **写入文件**（`Write` 工具）：`AI-测试用例/<module>/<功能名>_测试用例_<TIMESTAMP>.md`（UTF-8）
   - 如 `AI-测试用例/<module>/` 不存在则用 `Bash` 工具 `mkdir -p` 创建

### 第五步：汇总报告

处理完所有 MD 后，main flow 输出汇总报告。

## 平台特有规范（Web）

### 测试点 → 测试用例拆解原则

1. **功能测试点**：
   - 每个测试点拆解为 1-N 条具体测试用例
   - 正向测试点：至少生成 1 条正常流程用例
   - 反向测试点：生成异常校验用例（空值、格式错误、边界值）

2. **状态测试点**：
   - 加载状态 → 转化为"页面加载验证"用例
   - 交互状态 → 转化为"交互操作"用例（如点击、双击、右键、拖拽、键盘事件）
   - 窗口生命周期 → 转化为"最小化/最大化/关闭/多标签切换"用例

3. **边界条件测试**：
   - 直接转化为测试用例，测试数据使用边界值

4. **Web 补充测试点**：
   - 浏览器兼容：Chrome / Firefox / Safari / Edge 主流版本
   - 响应式布局：桌面（1920×1080）/ 平板（768×1024）/ 手机（375×667）三种视口
   - 键盘操作：Tab 键焦点顺序、Enter 提交、Esc 关闭模态框、方向键导航
   - 输入校验：HTML5 input type（email/url/tel/number/date）校验、required 属性、maxlength
   - 富交互：下拉菜单联动、日期范围选择、富文本编辑器、文件上传/下载、拖拽排序
   - 表单：提交前校验、提交后反馈（toast/alert/页面跳转）、重置按钮、必填项标记
   - 网络与异常：飞行模式、弱网/断网重连、API 失败重试、429 限流
   - 生命周期：页面刷新、关闭重开、返回按钮、URL 参数保留
   - 离线与异常：断网、服务异常、404/500 页面
   - 多端差异：与 H5/移动端的差异点
   - 安全：XSS 注入、CSRF、SQL 注入、暴力破解、敏感信息脱敏
   - 性能：首屏加载时间、列表分页加载、滚动懒加载
   - 无障碍：屏幕阅读器、键盘导航、ARIA 属性、颜色对比度
   - 以上每条测试点都必须拆解为独立的测试用例

### 测试数据说明

- 测试数据直接在测试步骤中使用占位符表示，如：`{{ 用户名 }}`、`{{ 登录密码 }}`
- 静态数据（格式校验、边界值）直接写具体值

### 测试步骤格式

强制使用操作步骤格式：`"字段名"控件类型 操作 操作值`

- **字段名**：控件的标签文字或 placeholder / name / id
- **控件类型**：输入框、密码框、按钮、单选框、复选框、下拉选项、模态框、日期选择器、富文本编辑器、文件上传 等
- **操作**：输入、选择、点击、勾选、清空、滑动、双击、键盘按键（Tab/Enter/Esc）、右键 等
- **操作值**：具体操作内容，使用 `{{ 占位符 }}` 表示动态数据

**示例（Web 登录）**：
1. "用户名"输入框 输入 {{ 用户名 }}
2. "密码"密码框 输入 {{ 登录密码 }}
3. 点击"登录"按钮
4. 按下 Enter 键
5. "记住我"复选框 勾选
6. "忘记密码"链接 点击
7. "验证码"输入框 输入 {{ 验证码 }}

### 预期结果具体化

| 测试点写法 | 转化为具体预期结果 |
|---------|--------------|
| 登录成功 | 跳转至首页，顶部导航显示用户名，localStorage 保存 token |
| 登录失败 | 错误信息显示在表单顶部，密码输入框聚焦 |
| 必填校验 | 未填字段下方显示红字提示，提交按钮变灰 |
| 模态框 | 弹窗居中显示，点击遮罩或 ESC 关闭 |
| 网络异常 | 顶部显示"网络异常"提示条，自动重试 3 次 |
| 页面刷新 | 表单数据保留（如有"草稿"功能），否则清空 |
| 响应式 | 视口缩放至 375px 时导航折叠为汉堡菜单 |

## 测试用例编号

每条用例使用 `uuid.uuid4().hex`（**32 位无横杠 hex 字符串**）作为唯一编号，**main flow 直接生成**。

> 不要用 `str(uuid.uuid4())`（36 位带横杠），也不要对带横杠字符串手动 `replace('-', '')`。
>
> 生成方式：main flow 自行在每条用例的"用例编号"字段填一个 UUID；无需额外 Bash 命令。

## ⚠️ Markdown 格式硬性要求

参见通用格式要求（同其他平台 case-gen）。重点：
- `##` 标题井号后必须留半角空格
- 列表 `-` / `1.` 后必须留半角空格
- 表格 `|` 两侧必须有空格
- 代码块用三反引号包围
- 生成后用 `grep -nE '^#{1,6}[^# ]' <file>` 复核

## 注意事项

1. **可指定单 MD 生成**——用户说"XXX 的用例"时直接处理该 MD，跳过扫描
2. **每次独立**——不读、不改、不合并已有用例文件
3. **整批共用一个时间戳**
4. **同 MD 多版本共存**——文件名带时间戳
5. **用户自己挑版本**——历史文件由用户决定保留哪个
6. **每个测试点文档一个 case MD**
7. **模块从测试点 MD 父目录推**
8. **测试数据使用占位符**：动态数据用 `{{ 占位符 }}`；静态数据直接写具体值
9. **预期结果必须具体**：禁止"提示正确"等模糊描述
10. **"字段名"控件类型 操作 操作值格式**
11. **不要推测**：只使用文档中已有的信息
12. **Web 无"平台"字段**：平台标记在文件标题中（"AI-测试用例"），不写在用例信息表里
13. **Web 控件必须覆盖**：表单、按钮、模态框、下拉菜单、日期选择器、富文本编辑器、文件上传，以及浏览器兼容、响应式、键盘操作、无障碍

## 与其他技能的关系

```
bigbear-web-testpoint        →  生成测试点分析文档
bigbear-web-case-generator   →  单个测试点 MD → case 文件（当前技能，main flow 直接处理，无 subagent）
bigbear-web-test-runner      →  执行用例（不在本技能范围）
```
